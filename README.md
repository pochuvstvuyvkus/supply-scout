# Supply Scout — поиск и сравнение поставщиков для общепита

**Прототип:** https://pochuvstvuyvkus.github.io/supply-scout/
**Код:** https://github.com/pochuvstvuyvkus/supply-scout

Сервис находит поставщиков продуктов и упаковки для ресторанов и доставки, собирает о них ключевую информацию
и помогает решить, с кем связаться первым. Главное требование, которое я себе поставил: **в карточке не может быть
выдуманного факта**. Каждый факт показан вместе с дословной цитатой с сайта поставщика и ссылкой на страницу,
откуда он взят.

## Что умеет

| Задача из ТЗ | Как сделано |
|---|---|
| Искать по категории товара | 10 категорий под HoReCa и доставку (рыба, рис, паназия, мясо, овощи, молочка, бакалея, заморозка, упаковка, хлеб) + поиск по тексту с учётом окончаний («лососи» → «лосось») |
| Учитывать город или регион | Екатеринбург и Москва; поставщики «по всей России» показываются в обоих городах, но с пометкой и меньшим весом. Город берётся из адреса, текста о регионах и **кода телефона** (343, 495/499) |
| Собирать основную информацию | Товары, город, адрес, регионы поставки, ИНН (с проверкой контрольной суммы) |
| Контакты, сайт, источник | Телефоны и почта извлекаются из HTML без модели; у каждого факта ссылка на страницу-источник |
| Помогать принять решение | Оценка 0–100 с объяснением «почему», кнопки «Что важнее» (документы, цена, доставка, малый заказ) меняют рейтинг, отдельная вкладка «Сравнение» до 4 поставщиков: карточки рядом, разделы по фактам, метка «ниже всех» у минимального заказа в рублях |
| Доп. данные | Минимальный заказ, цены, документы и сертификаты, условия доставки, регион работы, работа с HoReCa, годы на рынке, заметки |

Сверх ТЗ, потому что это нужно закупщику в работе:
- **«Уточнить при звонке»** — список вопросов только про то, чего на сайте нет;
- **готовый запрос КП** с этими вопросами: скопировать или открыть в почте;
- **окно поставщика** с вкладками «Обзор», «Источники» (все цитаты со ссылками) и «Заметка»;
- **«Мой список»** — воронка статусов: Новый → Связались → Запросили КП → Получили прайс → Работаем / Не подходит, заметки, выгрузка в CSV для Excel;
- **«Проверить контрагента»** по ИНН;
- **живой поиск** новых поставщиков по любому товару, когда запущен сервер (см. ниже).

## Как устроено

```
 поиск ──► сайт ──► модель ──► проверка без модели ──► карточка ──► оценка и решение
 Exa      главная   Gemini 2.5   цитата дословно на       только       под приоритеты
 (+DDG)   + 5 стр.  Flash,       странице? числа и        проверенные  пользователя
          контакты  JSON-схема   слова значения —         факты
          регэкспом с цитатами   из цитаты?
```

1. **Поиск** (`collector/search.py`). По каждой категории и городу — 2 запроса. Основной источник — веб-поиск Exa
   через OpenRouter, запасной — DuckDuckGo. Маркетплейсы, справочники, агрегаторы и СМИ отсекаются списком доменов.
2. **Сайт** (`collector/fetch.py`). Главная и до 5 внутренних страниц, выбранных по ссылкам: контакты, доставка,
   документы, условия для оптовиков, о компании. Телефоны (с проверкой кода) и почта — регулярными выражениями из HTML.
3. **Модель** (`collector/extract.py`). Gemini 2.5 Flash (запасная — GPT-4.1 mini) отвечает строго по JSON-схеме.
   К каждому факту обязана приложить дословную цитату и номер страницы. Тип сайта: поставщик, каталог, розничный
   магазин или другое.
4. **Проверка** (`collector/verify.py`) — ключевая часть, модель здесь не участвует:
   - цитата должна дословно найтись на странице (с нормализацией пробелов, регистра, ё/е, кавычек и тире)
     и быть короткой — до 250 символов; в карточке она показывается целиком;
   - все числа из значения должны быть в цитате: модель не может написать «от 7000 ₽», если на сайте «от 5 000 ₽»;
   - каждый пункт списка тоже должен быть в цитате (нельзя дописать «молочную продукцию» к «лососю»), а слов
     значения в цитате — не меньше 80%;
   - цитата должна относиться к полю: у цены рубли за товар (скидки, тарифы перевозки, «цены по запросу» и пороги
     бесплатной доставки отсекаются), у документов — сертификаты, декларации, «Меркурий», у доставки — конкретные
     условия, а не «быстрая доставка», у категории — её ключевые слова («Мороженое» не делает компанию поставщиком
     заморозки);
   - город берётся из цитат адреса и описания поставок, а не из виджета «Ваш город» и SEO-списков городов;
   - ИНН проверяется по контрольной сумме ФНС, ИНН веб-студии из подвала сайта не берётся;
   - каталоги, магазины для частных лиц, консалтинг и франшизы не становятся поставщиками;
   - без подтверждённой категории или без контактов карточка не создаётся.

   Всё отброшенное пишется в статистику с причиной (вкладка «Как это работает»).
5. **Оценка** (`web/js/core.js`). Взвешенная сумма: город, документы, цена, доставка, минимальный заказ, HoReCa,
   полнота данных. Приоритеты пользователя умножают вес пункта в 2,5 раза. В карточке видно, из чего сложилась оценка.

## Почему такой формат

- **Сбор офлайн + статичный интерфейс.** Закупщику важна скорость и надёжность: страница открывается мгновенно,
  не зависит от поисковика и модели в момент работы, её можно держать на GitHub Pages бесплатно.
  База обновляется конвейером по расписанию (раз в сутки или неделю).
- **Живой поиск через API.** Для нового товара, которого нет в базе, есть `GET /api/collect` — тот же конвейер для
  одного запроса с потоковым прогрессом (SSE). Включается сам, если интерфейс открыт с запущенного сервера.
- **Модель только извлекает, решает код.** Модель хороша в чтении неструктурированных сайтов, но может ошибаться.
  Поэтому её ответ — это гипотеза, а в карточку попадает только то, что подтвердил детерминированный проверяющий.
- **Дёшево.** Полный сбор по 10 категориям и 2 городам стоит около $1 (модель и поиск) и занимает несколько минут. Повторные
  запуски берут страницы и ответы модели из кэша.

## Проверки

```
pytest -q            # проверяющий (все случаи, когда факт должен быть отброшен), ИНН, контакты, API, инварианты базы
node --test tests/core.test.mjs   # фильтры, оценка, приоритеты, вопросы, запрос КП, CSV, сравнение
python scripts/audit.py           # независимый аудит: заново скачивает все страницы-источники и сверяет цитаты и телефоны
```

`scripts/audit.py` намеренно не использует код конвейера: он сам скачивает страницы, сам ищет цитаты, телефоны и
почту и сам сверяет числа значения с цитатой. Кроме автоматических проверок, код и данные просмотрел отдельный
агент-ревьюер; найденные им случаи (цитата не о том поле, слишком длинные цитаты, регион из SEO-текста, ИНН подрядчика)
закрыты правилами выше и тестами в `tests/test_verify.py`.
Результат последнего прогона — в `data/audit.json` и в разделе ниже.

Кроме аудита, два прохода сделал отдельный агент-ревьюер: читал карточки и искал факты, которые формально
подтверждены цитатой, но вводят закупщика в заблуждение (цитата не о том поле, категория по названию блюда,
город из SEO-фразы, ИНН подрядчика). Все найденные типы ошибок закрыты правилами и тестами в `tests/test_verify.py`.
Во втором проходе доля спорных фактов была около 3%, после этого добавлены правила для категорий, документов,
минимального заказа и телефонов-заглушек.

Расхождение в аудите — не ошибка сбора, а изменившийся сайт; поэтому база пересобирается по расписанию,
а у карточки видна дата проверки.

## Запуск

```bash
uv venv && uv pip install -r requirements.txt
echo "OPENROUTER_API_KEY=..." > .env

python -m collector.pipeline                                  # полный сбор → data/suppliers.json
python -m collector.pipeline --query "нори" --city Екатеринбург   # один запрос
uvicorn api.main:app --port 8000                              # интерфейс + API + живой поиск
```

Интерфейс без сервера: `python -m http.server -d web 8791` (работает на собранной базе).
